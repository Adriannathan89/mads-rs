# MADS v0.8.0 Input Validation Model and Derive Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the transport-independent `Input` contract, ordered validation issues, the complete built-in validator matrix, and `#[derive(Input)]` before connecting validation to Axum request extraction.

**Architecture:** `mads-common` owns public validation values and small hidden validator/traversal helpers. `mads-common-macros` parses `#[validate(...)]` plus the Serde metadata required for external paths and generates deterministic traversal for structs and active enum variants. Manual implementations and custom callbacks return the same ordered `ValidationResult`; no validator performs I/O or async work.

**Tech Stack:** Rust 2024, Rust 1.85 MSRV, `syn`/`quote`, Serde derive metadata, deterministic standard collections, trybuild, and existing MADS facade feature composition.

**Spec:** `docs/superpowers/specs/2026-09-06-v0.8.0-input-validation-design.md`

## Global Constraints

- This is Plan 2 of 8 and begins after Plan 1 establishes `0.8.0-beta.1`.
- Public validation APIs live in `mads-common` and are available only with `http`; do not create another public crate.
- The derive remains named `Input` and must coexist with the `Input` trait through Rust's separate namespaces.
- Validation occurs only after Serde has successfully created a Rust value; do not implement coercion, transformation, or another schema deserializer.
- Collect all independent post-deserialization issues in declaration, validator, index, lexical map-key, then whole-value callback order.
- Built-ins and generated diagnostics never contain rejected values. Custom codes/messages are application-owned safe text.
- String length counts Unicode scalar values. Email follows the frozen practical Zod-default vectors with no normalization or DNS lookup.
- Hash maps must be sorted lexically by string key before nested traversal.
- Do not add database, JWT, or cookie requirements to validation.
- Keep ordinary Axum `Json`, `Query`, and `Path` behavior unchanged; validated extractors arrive in Plan 3.

```rust
struct ManualInput;

impl Input for ManualInput {
    fn validate(&self) -> ValidationResult {
```

- [ ] **Step 3: Implement the transport-independent model**

Use private issue fields and public read-only accessors:

```rust
pub trait Input {
    fn validate(&self) -> ValidationResult;
}

pub type ValidationResult = Result<(), ValidationErrors>;

pub enum ValidationPathSegment {

}
```

- [ ] **Step 3: Implement safe validator primitives**

Centralize issue construction so codes/messages cannot drift:

```text
required          -> required value is missing
invalid_type      -> input has an invalid type
invalid_syntax    -> input syntax is invalid
invalid_format    -> invalid email address
too_small         -> value is too small
too_big           -> value is too big
not_multiple_of   -> value is not a multiple of the required number
```

Count strings with `.chars().count()`. Use exact `%` for integers. For floats,
reject non-finite values first and compare the quotient to its nearest integer
using a tolerance derived from the declared decimal precision and machine
epsilon; never compare a raw floating remainder directly. Sort collected hash-
map keys before traversing nested values.

- [ ] **Step 1: Write derive runtime and compile cases**

Start with:

```rust
#[derive(serde::Deserialize, Input)]
#[serde(rename_all = "camelCase")]
struct CreateUser {
    #[validate(email, length(max = 254))]
    email_address: String,
    #[validate(required, nested)]
    profile: Option<ProfileInput>,
}
```

Add named, tuple, and unit structs; named/tuple/unit enum variants; externally,
internally, adjacently tagged, and untagged enums; renamed variants/fields;
flattened fields; aliases/defaults; tuples/arrays/vectors; and both supported
map types. For aliases, validate the canonical Serde field path after either
the primary or alias spelling successfully deserializes.

Add compile failures for unknown/duplicate attributes, incompatible validator
types, `negative` on unsigned integers, `required` on non-options, zero
multiples, overflowing literals, contradictory/exact length forms, minimum
above maximum, and unsupported automatic collection/map shapes.

- [ ] **Step 2: Run derive and UI suites before the macro exists**

- [ ] **Step 3: Implement strict macro parsing and deterministic generation**

Register:

```rust
#[proc_macro_derive(Input, attributes(validate))]
pub fn input(input: TokenStream) -> TokenStream {
    syn::parse(input)
        .and_then(input::expand)
        .unwrap_or_else(syn::Error::into_compile_error)
        .into()
}
```

Parse validators in lexical attribute/list order. Generate validation only for
the active enum variant. Generate canonical Serde paths according to the
approved representation rules; flatten suppresses its container segment.
Automatic non-finite checks run for every derived float field before declared
numeric validators. Emit `syn::Error` at invalid attributes/literals/types and
one minimal trait assertion for `nested` bounds.
