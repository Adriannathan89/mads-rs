# MADS v0.8.0 Minimal Project Scaffolding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an offline, atomic `mads new <name>` command that creates exactly the approved seven-file HTTP/Tokio application, reports through human or schema-v1 JSON output, and works outside an existing Cargo project.

**Architecture:** Bundle fixed source templates inside `mads-cli`. Validate the name and all syntax before touching the filesystem, render every file into a uniquely created sibling staging directory, then publish the complete directory with a no-replace atomic rename. Dispatch the resulting structured scaffold data through Plan 6's output layer. Generated-consumer tests substitute only the exact MADS dependency source with a local path after snapshotting the real manifest.

**Tech Stack:** Rust 2024, Rust 1.85 MSRV, standard filesystem APIs, `rustix` no-replace rename on Linux/macOS, Windows directory rename semantics, embedded `include_str!` templates, Serde JSON output, Cargo metadata/check in test fixtures, and live TCP HTTP verification.

**Spec:** `docs/superpowers/specs/2026-09-06-v0.8.0-project-scaffolding-design.md`

## Global Constraints

- This is Plan 7 of 8 and begins after Plan 6 establishes the shared finite-command output model.
- `mads new <name>` creates only `./<name>` and exactly seven documented files.
- Validate against the approved lowercase grammar, Cargo 1.85 reserved names, and Rust 2024 strict/reserved keywords; never normalize or rename input.
- Reject every existing target discovered through `symlink_metadata`, including an empty directory, file, ordinary symlink, or dangling symlink.
- Validate before staging. On failure, remove only the staging directory created by this invocation; never modify a pre-existing destination or unrelated sibling.
- Publish with one atomic no-replace rename. A destination race must fail without replacement.
- Do not invoke Cargo, rustc, Git, a network client, a package registry, or a remote template during generation.
- Generated package version is `0.1.0`; generated MADS dependency is exactly the running CLI package version and enables only `http` and `runtime-tokio` with defaults disabled.
- Do not generate database, migrations, schema, JWT, cookies, Passport, authentication, `.env`, README, lockfile, Git metadata, or `target` files.
- Name validation failures exit 2; filesystem/template/publication failures exit 1; success exits 0.
- JSON failure before publication uses `data: null`; successful files remain in the approved deterministic order.

```rust
use mads::prelude::*;
```

```rust
    service: AppService,
}

    async fn hello(&self) -> &'static str {
        self.service.hello()
    }
}
```

### Task 2: Stage and atomically publish a complete project

**Files:**
- Create: `crates/mads-cli/src/scaffold/publish.rs`

**Interfaces:**
- Consumes: invocation directory, validated name, and rendered manifest.
- Produces: a fully published child directory or no destination at all.

- [ ] **Step 1: Add filesystem safety and failure-injection tests**

Test generation in an empty non-Cargo directory; exact seven-file recursive
layout; existing file/directory rejection; ordinary and dangling symlink
rejection where supported; read-only/write failure injection; a destination
created immediately before rename; unrelated sibling preservation; and staging
cleanup after every pre-publication failure. Assert the destination race's
sentinel remains untouched.

- [ ] **Step 2: Run filesystem tests before publication exists**

```bash
cargo test -p mads-cli --test scaffold_cli filesystem
```

Expected: FAIL because generation/publication is not implemented.

- [ ] **Step 3: Implement guarded staging and no-replace rename**

Check destination with `symlink_metadata`, treating only `NotFound` as absent.
Create a sibling `.<name>.mads-<pid>-<counter>.tmp` directory with
`create_dir`; retry only staging-name collisions. A guard owns exactly that
path and removes it recursively until disarmed. Create subdirectories, write
files with `create_new`, flush/sync files, and synchronize the staging
directory when supported.

Publish once: use `rustix::fs::renameat_with(..., RenameFlags::NOREPLACE)` on
Linux/macOS and `std::fs::rename` for an absent directory destination on
Windows, where replacement of an existing directory is rejected. For other
targets, fail safely if atomic no-replace directory publication is unavailable.
Disarm only after rename success. Convert every failure to MADS230 with safe
stage-specific wording and retained private source.

- [ ] **Step 4: Repeat race and cleanup tests**

```bash
cargo test -p mads-cli --test scaffold_cli filesystem -- --test-threads=1
```

Expected: PASS; no test leaves a `.mads-*.tmp` sibling.
