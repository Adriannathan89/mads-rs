# MADS v0.8.0 HTTP Errors and Validated Extractors Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the seven-type REST error family, normalize every MADS-owned HTTP rejection into one safe JSON envelope, and enforce deserialize-then-validate behavior through explicit `ValidatedJson`, `ValidatedQuery`, and `ValidatedPath` wrappers.

**Architecture:** Refactor `response.rs` around one internal response description shared by `Display` and `IntoResponse`. Keep validation issues unsourced until the request boundary, then convert them into public sourced issues before constructing `ValidationError`. Delegate representation parsing to the corresponding Axum extractor so custom Serde behavior stays authoritative, classify its rejection without echoing native text, and invoke `Input::validate` only after successful deserialization.

**Tech Stack:** Rust 2024, Rust 1.85 MSRV, Axum 0.8 extractors and rejections, Serde/Serde JSON, `serde_path_to_error`, `serde_urlencoded`, Tower in-process requests, existing Passport/cookie integrations, and MADS generated routes.

**Spec:** `docs/superpowers/specs/2026-09-06-v0.8.0-rest-errors-diesel-mapping-design.md` and `docs/superpowers/specs/2026-09-06-v0.8.0-input-validation-design.md`

## Global Constraints

- This is Plan 3 of 8 and begins after Plan 2 completes the `Input` model and derive.
- Keep native `Json<T>`, `Query<T>`, `Path<T>`, arbitrary Axum responses, middleware, and routers unchanged.
- Preserve `HttpError::bad_request`, `not_found`, `conflict`, and `internal`, including the existing stable `internal` response code.
- Every MADS-owned response uses `application/json` and the common `{"error": ...}` envelope.
- Validation issues always contain exactly one explicit `body`, `query`, or `path` source; never infer a source inside `ValidationError::new`.
- Serde conversion remains fail-fast. Post-conversion `Input` validation remains collect-all.
- Do not serialize or format rejection/source details. Application-supplied standard/custom messages remain the application's safety responsibility.
- Passport 401 alone preserves `WWW-Authenticate: Bearer`; a normal `Unauthorized` does not add it.
- JSON transport errors retain 413/415 semantics; schema conversion failures are 422.
- Do not introduce database mapping in this plan; Plan 4 owns it.

**Interfaces:**
- Produces: `ValidatedJson<T>(pub T)` and `into_inner`.
- Enforces: representation → owned Serde value → `Input::validate` → handler.

- [ ] **Step 1: Write in-process JSON request tests**

Create an Axum router with a shared atomic handler counter and test:

- valid JSON returns success and increments once;
- malformed syntax and type/required conversion failures return one sourced
  422 issue with `invalid_syntax`, `invalid_type`, or `required`;
- post-conversion validators return every issue in derive order;
- missing/wrong content type returns 415 `unsupported_media_type` with
  `content type must be application/json`;
- configured body-limit overflow returns 413 `payload_too_large` with
  `request body is too large`;
- other client body-read failures return safe 400 `bad_request`; and
- server-class read failures return fixed redacted 500.

For every invalid request, assert the handler counter remains zero.

- [ ] **Step 2: Run JSON extractor tests before implementation**

```bash
cargo test -p mads-common --no-default-features --features http --test validated_extractors json
```

Expected: FAIL to compile because `ValidatedJson` is absent.

- [ ] **Step 3: Implement delegation and safe rejection classification**

Add `serde_path_to_error` and `serde_urlencoded` as explicit workspace
dependencies used by the `http` feature. Call Axum's `Json<T>` extractor for
`T: DeserializeOwned + Input`; never deserialize twice. Inspect typed rejection
variants/status and their structured error chain for safe path/category data.
Parse only the explicitly regression-tested Serde missing-field form to recover
a required field path; classify other data conversion failures as
`invalid_type`, and never reuse native error text as a client message. Convert
successful `ValidationErrors` with:

```rust
let issues = errors
    .into_issues()
    .into_iter()
    .map(|issue| issue.with_source(ValidationSource::Body));
ValidationError::new(issues)
```

If a body rejection is not a schema error, map 415 and 413 first, then client-
class status to safe 400 and server-class status to redacted 500.
