# MADS v0.8.0 Opt-In Diesel HTTP Mapping Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the explicit `.into_http()` policy boundary for MADS `DatabaseResult<T>` and native Diesel `QueryResult<T>`, mapping only not-found and unique violations to safe client responses and redacting every other database failure.

**Architecture:** Put the extension trait beside the database integration and compile it only for `http + database`. Normalize both supported result aliases through one typed Diesel classifier. Use private source-retaining constructors on standard HTTP errors so mapped 404/409 failures retain their originating error without adding any blanket `From<DatabaseError>` conversion.

**Tech Stack:** Rust 2024, Rust 1.85 MSRV, Diesel 2.2 typed errors, MADS database normalization, Axum response tests, trybuild negative API coverage, and Linux PostgreSQL integration tests.

**Spec:** `docs/superpowers/specs/2026-09-06-v0.8.0-rest-errors-diesel-mapping-design.md`

## Global Constraints

- This is Plan 4 of 8 and begins after Plan 3 completes standard HTTP errors.
- Export `IntoHttpResult<T>` only when both `http` and `database` are enabled.
- Implement exactly two result conversions: `Result<T, DatabaseError>` and `diesel::QueryResult<T>`.
- Do not implement `From<DatabaseError> for HttpError`, route-level automatic mapping, or blanket result conversions.
- Classify conflict only through Diesel's typed `UniqueViolation`; never parse backend text or constraint names.
- Map `NotFound` to 404 `resource not found`, unique violation to 409 `resource already exists`, and everything else to fixed redacted 500.
- Preserve the complete original source chain while keeping SQL, URLs, values, constraints, tables, columns, and backend messages out of client and ordinary formatting output.
- Keep database-only builds free of Axum and HTTP-only builds free of Diesel.
- Real PostgreSQL evidence runs only in the Linux database job.

### Task 1: Implement pure typed classification for both result families

**Files:**
- Create: `crates/mads-common/src/database/http.rs`
- Modify: `crates/mads-common/src/database/mod.rs`
- Modify: `crates/mads-common/src/response.rs`
- Modify: `crates/mads-common/src/lib.rs`
- Create: `crates/mads-common/tests/database_http.rs`

**Interfaces:**
- Produces: `pub trait IntoHttpResult<T> { fn into_http(self) -> HttpResult<T>; }`.
- Consumes: `DatabaseError` and `diesel::result::Error` by value so the selected HTTP error can retain the source.

- [ ] **Step 1: Write pure result-mapping tests**

Exercise native results:

```rust
let missing: diesel::QueryResult<()> = Err(diesel::result::Error::NotFound);
let response = missing.into_http().unwrap_err().into_response();
assert_eq!(response.status(), StatusCode::NOT_FOUND);
```

Implement a test-only `DatabaseErrorInformation` carrying sentinel constraint,
table, column, details, and hint values; wrap it in
`Error::DatabaseError(DatabaseErrorKind::UniqueViolation, ...)` and require the
exact conflict body. Test representative non-unique database errors and MADS
`DatabaseError::Query` for 500. Inspect the mapped standard error's source
before response conversion and scan all formatting/response bytes for every
sentinel.

- [ ] **Step 2: Run mapping tests before the trait exists**

```bash
cargo test -p mads-common --no-default-features --features http,database --test database_http
```

Expected: FAIL to compile because `IntoHttpResult` is absent.

- [ ] **Step 3: Implement one classifier and two exact impls**

Add:

```rust
pub trait IntoHttpResult<T> {
    fn into_http(self) -> HttpResult<T>;
}

impl<T> IntoHttpResult<T> for Result<T, DatabaseError> {
    fn into_http(self) -> HttpResult<T>;
}

impl<T> IntoHttpResult<T> for diesel::QueryResult<T> {
    fn into_http(self) -> HttpResult<T>;
}
```

Match only `Error::NotFound` and
`Error::DatabaseError(UniqueViolation, _)`; move the original error into a
private source-retaining `NotFound`/`Conflict` constructor. Move all other
native errors and every non-query `DatabaseError` into `InternalError`. The
client serializer must have no access to the source object.

- [ ] **Step 4: Verify exact statuses, bodies, chains, and redaction**

```bash
cargo test -p mads-common --no-default-features --features http,database --test database_http
cargo test -p mads-common --no-default-features --features http --test response
```

Expected: PASS; adding source retention does not change normal named-error
responses.

- [ ] **Step 5: Commit the extension trait**

```bash
git add crates/mads-common/src/database/http.rs crates/mads-common/src/database/mod.rs crates/mads-common/src/response.rs crates/mads-common/src/lib.rs crates/mads-common/tests/database_http.rs
git commit -m "feat(database): add opt-in HTTP result mapping"
```
