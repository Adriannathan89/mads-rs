# MADS v0.8.0 Beta Baseline and Typed Configuration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the workspace to the complete `0.8.0-beta.1` development version and add explicit, source-aware typed configuration plus redacted `Secret<T>` values without changing the existing configuration-loading chain.

**Architecture:** Keep `Config` as the immutable merged document. Add a prefix-aware `Configuration` runtime in `mads-core` and generate field traversal in `mads-core-macros`; the derive aggregates ordered issues and never performs I/O. `Secret<T>` stays a core value wrapper. Existing `ConfigBuilder`, dotenv interpolation, TOML loading, and final `MADS_*` environment overrides remain the only loading path.

**Tech Stack:** Rust 2024, Rust 1.85 MSRV, `syn`/`quote` procedural macros, existing `mads-core` diagnostics and configuration provenance, TOML/dotenv sources, Cargo feature tests, and trybuild.

**Spec:** `docs/superpowers/specs/2026-09-06-v0.8.0-typed-configuration-secrets-design.md`

## Global Constraints

- This is Plan 1 of 8 and has no implementation-plan prerequisite.
- Set every workspace package and exact internal path dependency to `0.8.0-beta.1`; the application generated later still starts at `0.1.0`.
- Do not add Serde, Axum, Diesel, JWT, or cookie dependencies to `mads-core`.
- Typed parsing must read only the supplied `&Config`; it must not inspect files, process environment, parent directories, or `CARGO_MANIFEST_DIR`.
- Preserve `.env` interpolation → optional `mads.toml` → final scalar `MADS_*` override behavior exactly.
- Aggregate failures in declaration order, recursively preserving nested order, and never include configured values in errors.
- Unknown keys remain allowed. Unsupported document shapes remain unsupported.
- `Secret<T>` must not implement `Deref`, `AsRef`, `Borrow`, or serialization and must not claim generic zeroization.
- Keep `#![deny(missing_docs)]`, `#![forbid(unsafe_code)]`, Rust 1.85, and the 85% line-coverage gate.

- [ ] **Step 3: Add the trait and safe parse helpers**

Implement:

```rust
pub trait Configuration: Sized {
    fn from_config(config: &Config) -> ConfigurationResult<Self>;
}

impl Config {
    pub fn parse<T: Configuration>(&self) -> ConfigurationResult<T> {
        T::from_config(self)
    }
}
```

Add documented hidden helpers for generated prefix-aware reads of scalar,
string-array, table, descendant presence, source label, and source-relative
path data. Add a documented hidden default trait method that projects the
supplied `Config` beneath a composed prefix and then calls the public
`Configuration::from_config`; this lets both derived and manual nested types
reuse the same public implementation without performing I/O or manually
stripping keys. The projected document clones only matching values/tables and
preserves their complete origins, so `resolve_path` and source labels remain
correct. Helpers return safe reason codes rather than formatting parser errors
or values. Float parsing rejects non-finite results as `invalid_type`. Do not
alter public `Config::get`, `iter`, or provenance behavior.
