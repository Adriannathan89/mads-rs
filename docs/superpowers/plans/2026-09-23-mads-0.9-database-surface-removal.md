# MADS.rs 0.9 Database Surface Removal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Retire the Diesel-backed framework database and migration CLI surfaces, while keeping explicitly imported native SeaORM persistence and releasing the CLI with the 0.9 workspace.

**Architecture:** Remove the old integration at its existing crate and CLI boundaries; leave `mads-core` and `mads-persistence` behavior unchanged. Let `mads-cli` inherit the workspace version and publish it after framework dependencies in both release workflows. Keep the existing parser, output, release, and CI structures rather than reorganizing them.

**Tech Stack:** Rust 2024, Rust 1.94, Cargo, SeaORM 2.0, PostgreSQL 16, Bash, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-23-mads-0.9-database-surface-removal-design.md`

## Global Constraints

- Preserve `mads-core` provider and lifecycle APIs and `mads-persistence`'s native `DatabaseConnection`, typed errors, safe formatting, ping-before-serve, and graceful close.
- Remove public `mads-common/database` and `mads/database` features and their Diesel APIs completely; no compatibility shim or automatic HTTP mapping.
- Keep `mads`'s `common` aggregate, now HTTP plus logger only; persistence is available solely through an explicit `mads-persistence` dependency/import with `sea-orm-postgres`.
- Remove `mads db` and all four database JSON data types; unknown top-level commands exit 2.
- All framework packages and `mads-cli` use workspace version 0.9.0, with exact internal `=0.9.0` pins. Future release scripts advance CLI with the workspace.
- Publish `mads-cli` after `mads-core-macros`, `mads-common-macros`, `mads-core`, `mads-persistence`, `mads-extra`, `mads-common`, and `mads` in both beta and stable workflows.
- Preserve HTTP, JWT, cookies, logger, CLI `new`/`run`/`dev`/`routes`/`graph`/`doctor`, current JSON schema for those commands, PostgreSQL persistence tests, coverage gate, protected environments, and existing workflow retry policies.
- Minimize refactoring: change only affected branches, modules, fixtures, manifests, scripts, tests, and active documentation. Historical 0.8 documents remain archival.
- Use red-green-refactor for behavior changes, `apply_patch` for edits/removals, and focused commits at each task boundary.

## Review Focus

- `mads db`, `mads db status`, and `mads --format json db status` must all fail as unknown top-level commands with exit 2; Task 3 adds process tests, including the JSON context.
- `mads` default, `mads` no-default, and ordinary `mads-cli` dependency trees must exclude Diesel and libpq; Tasks 2 and 3 add tree assertions.
- HTTP, JWT, and cookie feature combinations must still compile without database; Task 2 keeps and extends the feature matrix.
- A release fixture that previously held a literal CLI version must not silently retain it or accept `--keep-cli-version`; Task 4 tests both paths.
- A release workflow must not publish CLI before a framework dependency is visible or drop the SeaORM PostgreSQL gate; Task 5 pins order and gate content.
