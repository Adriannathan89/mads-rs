MADS is a Rust framework for building modular services. Its central idea is simple: your application declares what it contains, and MADS constructs only that selected graph. You do not need to understand modules, providers, HTTP, or databases before reading this page.

## The MADS approach

Start with an application root. It selects feature modules; those modules make the routes and dependencies for that application reachable. MADS validates the selected graph before it starts lifecycle hooks or opens a listener.

That keeps composition visible. A service is not created just because a crate is in `Cargo.toml`, and a database is not started just because a database feature is enabled. It becomes part of the running application only when the selected graph needs it.

## What MADS gives you

- An explicit composition model for modular Rust applications.
- A provider graph for constructing dependencies without global initialization.
- Optional HTTP, configuration, database, JWT, cookie, and migration integrations.
- Startup validation before a partially configured service begins serving requests.

## What stays under your control

MADS does not require one architecture or ORM. Use its Diesel database integration when it fits, or provide your own connection and repository implementation. The framework coordinates the graph; your application chooses its boundaries, contracts, and infrastructure.

## Follow the learning path

Continue with **Getting started** to run an application, then **Fundamentals** to learn the module and provider rules. Configuration, HTTP delivery, and data integrations build on those concepts in that order.
