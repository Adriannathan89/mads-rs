`mads new` creates seven source and configuration files. The shape is small on purpose: it gives you a clear HTTP boundary without assuming persistence or authentication.

```text
my-app/
├── Cargo.toml
├── mads.toml
└── src/
    ├── main.rs
    └── app/
        ├── mod.rs
        ├── routes.rs
        ├── controller.rs
        └── service.rs
```

## The application module

`src/app/mod.rs` owns the module declaration. `routes.rs` describes routes, `controller.rs` owns HTTP delivery, and `service.rs` is the first application behavior boundary.

### The composition root

`src/main.rs` is the only process entry point. It defines the root module, imports the application module, and calls `Mads::run::<AppModule>().await`.

## What is not generated

The starter has no database schema, migration, JWT secret, cookie policy, or login flow. Add each capability only when the application needs it.
